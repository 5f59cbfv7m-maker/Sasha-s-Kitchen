# Контракт API магазина

Клиент без этого файла не написать, поэтому он есть. Формат обмена намеренно
обычный JSON поверх HTTPS, без единой конструкции, специфичной для Apple: то же
самое прочитают Android и Windows, когда до них дойдёт очередь.

Все пользовательские тексты — на русском. Комментарии в коде и логи — на
английском.

## Общие правила

**Аутентификация.** `Authorization: Bearer <access token>`. Витрина, страницы
авторов, посты и комментарии читаются и без токена: отсутствие входа означает
анонимного читателя, а не отказ.

**Ошибки.** Один конверт на все случаи:

```json
{"error": {"code": "validation_failed",
           "message": "Проверьте заполненные поля",
           "fields": {"title": "Название от 1 до 140 символов"}}}
```

`code` — машиночитаемый: `bad_request`, `validation_failed`, `unauthorized`,
`forbidden`, `not_found`, `conflict`, `gone`, `rate_limited`,
`payload_too_large`, `internal_error`, `service_unavailable`.
`fields` появляется только у `validation_failed` (422) и ключуется именем поля
запроса.

**404 вместо 403.** Чужой медиафайл, страница заблокировавшего вас автора,
поверхность модератора — всё это отвечает «не найдено». Подтверждение того, что
объект существует, само по себе сведения.

**Постраничная навигация — курсорная.** Ответ листинга:

```json
{"items": [...], "next_cursor": "eyJ2IjoyLCJ...", "has_more": true}
```

Курсор непрозрачен, безопасен для URL и несёт сортировку, под которой выдан.
Листать одну сортировку курсором другой нельзя — это молча пропускало бы и
повторяло карточки, поэтому такой запрос отвергается (422). У ранжированной
ленты курсор дополнительно привязан к поколению пересчёта.

**ETag.** Все GET отдают `ETag`; с `If-None-Match` ответ становится 304.
Ответы, зависящие от читателя (его подписки, его комментарии), дополнительно
несут `Cache-Control: private, no-store` — их нельзя класть в общий кэш.

## Витрина

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/v1/storefront` | Полки главной. Подписчику первой идёт «Новое у тех, на кого вы подписаны» |
| `GET` | `/v1/taxonomy` | Категории, кухни, диетические метки |
| `GET` | `/v1/recipes` | Поиск и фильтры |
| `GET` | `/v1/recipes/facets` | Счётчики для фильтров: сколько найдётся при каждом значении |
| `GET` | `/v1/recipes/{id}` | Карточка рецепта; принимает и slug |
| `GET` | `/v1/recipes/{id}/bundle` | Самодостаточный payload для импорта в приложение |

Фильтры `/v1/recipes`: `q`, `category`, `cuisine`, `diet`, `difficulty`,
`cook_time_min/max`, `kcal_min/max`, `protein_*`, `fat_*`, `carbs_*`,
`include` (все перечисленные продукты есть), `exclude` (аллергия: отсекает
рецепт, где продукт встречается даже как необязательный), `pantry` +
`can_cook_now`, `access`, `has_video`, `author`, `sort`, `limit`, `cursor`.

`sort`: `relevance` (только с `q`), `new`, `popular`, `rating`, `quick`, `light`.

## Страницы авторов

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/v1/authors/top` | Таблица лидеров |
| `GET` | `/v1/authors/{handle}` | Профиль: шапка, счётчики, закреплённое, бейдж топа |
| `GET` | `/v1/authors/{handle}/recipes` | Полка рецептов; принимает те же фильтры, что и витрина |
| `GET` | `/v1/authors/{handle}/posts` | Блог |
| `GET` | `/v1/authors/{handle}/shorts` | Короткие видео |
| `PUT` `DELETE` | `/v1/authors/{handle}/follow` | Подписка. Идемпотентна, 204 |

`{handle}` принимает и псевдоним, и идентификатор. Переименование автора не
ломает уже разосланные ссылки: старый псевдоним продолжает вести к нему, а
ответ несёт текущий — клиенту стоит поправить у себя адрес. Живой псевдоним
всегда выигрывает у истории, потому что удаление аккаунта освобождает псевдоним
для повторной регистрации.

## Публикации и короткие видео

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/v1/posts/{id}` | Пост целиком, с разрешёнными блоками |
| `GET` | `/v1/shorts` | Общая вертикальная лента. `sort=new` (по умолчанию) или `top` |

Тело поста — массив типизированных блоков: `paragraph`, `heading`, `quote`,
`list`, `photo`, `gallery`, `video`, `recipe`. На чтении идентификаторы уже
разрешены: блок несёт готовые URL медиа и целую карточку рецепта. Ключи
хранилища клиенту не отдаются никогда — только адреса CDN.

Блок, который не удалось разрешить (медиа ещё кодируется, рецепт сняли),
из ответа исчезает, а не приходит поломанным.

## Комментарии

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/v1/{recipes\|posts}/{id}/comments` | Ветка: корни постранично, под каждым — первые ответы |
| `POST` | `/v1/{recipes\|posts}/{id}/comments` | Написать. `parent_id` — ответ |
| `DELETE` | `/v1/comments/{id}` | Удалить свой |

Один уровень ответов. Ответить можно только на комментарий верхнего уровня и
только под той же публикацией — это обеспечивает база, а не проверка в коде.
Ограничение частоты — на аккаунт: 10 в минуту, дальше 429.

## Безопасность контента

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/v1/reports` | Пожаловаться: `target_type` (recipe, user, rating, post, comment), `target_id`, `reason`, `details` |
| `GET` | `/v1/blocks` | Кого я заблокировал |
| `PUT` `DELETE` | `/v1/blocks/{id}` | Заблокировать и разблокировать |

Блокировка действует в обе стороны и снимает взаимные подписки. Повторная
жалоба на тот же объект отвечает 409: она уже принята.

`reason`: `spam`, `offensive`, `copyright`, `unsafe_food`, `sexual`, `other`.

## Медиа

Три шага, оригинал через сервер не проходит:

1. `POST /v1/media/uploads` → 201 с тикетом: `asset_id`, `upload_url`,
   `method` (`PUT`), `expires_in_seconds`, `max_bytes`.
2. Клиент кладёт файл `PUT`-ом прямо в хранилище по `upload_url`.
3. `POST /v1/media/{id}/complete` → сервер сверяет фактический размер и тип с
   заявленными и ставит задачу на обработку.

Дальше `GET /v1/media/{id}` до `status: "ready"`. Видео отдаётся манифестом HLS
с постером, фото — напрямую; оригиналы не публикуются.

Фото: `image/jpeg`, `image/png`, `image/heic`, `image/webp`, до 25 МБ.
Видео: `video/mp4`, `video/quicktime`, до 2 ГБ; длина ограничена уровнем
доверия автора.

**Неприкреплённый файл живёт сутки.** Сборщик мусора удаляет медиа, на которое
никто не ссылается, но не раньше суток после загрузки — иначе он съедал бы
файлы, пока автор дописывает статью.

## Студия автора

Всё под `/v1/me/` требует входа и работает только со своим.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/v1/me/stats` | Панель: уровень доверия, лимит суток, что на проверке |
| `PATCH` | `/v1/me/profile` | Частичная правка: имя, био, ссылки, аватар, обложка, закреплённое, псевдоним |
| `GET` `POST` | `/v1/me/recipes` | Свои рецепты во всех состояниях; создать черновик |
| `PATCH` `DELETE` | `/v1/me/recipes/{id}` | Правка и удаление |
| `POST` | `/v1/me/recipes/{id}/submit` | Публикация |
| `GET` `POST` | `/v1/me/posts` | То же для публикаций |
| `PATCH` `DELETE` | `/v1/me/posts/{id}` | |
| `POST` | `/v1/me/posts/{id}/submit` | |

Ответ на `submit`: `{"status": "published"|"review", "published_at": ...}` —
доверенный автор публикуется сразу, новичок уходит на проверку.

**Лимит суток** зависит от уровня доверия: новичок — 3, доверенный — 10,
проверенный — 30. Превышение даёт 429. Считаются отправки, а не публикации:
один черновик, отправленный трижды, потратит три.

**Уровни доверия.** Первые три одобренные публикации проходят премодерацию,
после чего автор публикуется напрямую. Подтверждённое снятие возвращает его
обратно и обнуляет прогресс. Правка уже опубликованного возвращает
премодерируемого автора на проверку.

Ингредиент несёт **полное** определение продукта — название, единицу, вес
единицы, КБЖУ на 100 г, срок хранения, порог «мало». Это то, что позволяет
приложению создать незнакомый продукт без второго запроса и замораживает цифры
автора.

Платные рецепты API создавать отказывается: колонки в схеме есть, покупок нет.

## Модерация

Всё под `/v1/admin/` отвечает 404 тем, кто не модератор.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/v1/admin/queue` | Очередь: рецепты и публикации, сперва те, на что жалуются |
| `GET` | `/v1/admin/reports` | Открытые жалобы |
| `POST` | `/v1/admin/reports/{id}/resolve` | `{"status": "upheld"\|"dismissed"}` |
| `POST` | `/v1/admin/content/{recipe\|post}/{id}/approve` | Опубликовать |
| `POST` | `/v1/admin/content/{recipe\|post}/{id}/reject` | Вернуть автору; причина обязательна |
| `POST` | `/v1/admin/content/{recipe\|post}/{id}/takedown` | Снять опубликованное; причина обязательна |
| `POST` | `/v1/admin/users/{id}/suspend` | Приостановить аккаунт |
| `PUT` `DELETE` | `/v1/admin/users/{id}/verify` | Галочка проверенного автора |

Повторное одобрение сохраняет исходную дату публикации: исправленная опечатка
не должна выбрасывать рецепт обратно на вершину полки «новое».

## Аккаунты

| Метод | Путь |
|---|---|
| `POST` | `/auth/register`, `/auth/login`, `/auth/refresh`, `/auth/logout`, `/auth/apple` |
| `GET` `DELETE` | `/auth/me` |

`DELETE /auth/me` — удаление аккаунта из приложения, которого требует
рекомендация App Store 5.1.1(v). Псевдоним при этом освобождается.

## Служебное

`GET /healthz` — процесс жив. `GET /readyz` — база и хранилище отвечают.
